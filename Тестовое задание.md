# Техническое задание: Мини-сервис поиска авиабилетов (Next.js)

1. Требуется разработать упрощенную версию сервиса для поиска и выбора авиабилетов
2. Решение предоставить в виде ссылки на публичный репозиторий (GitHub / GitLab) с краткой инструкцией в `README.md`, как запустить проект и настроить mock-сервер

## Стек технологий

- **Фреймворк:** Next.js (App Router или Pages Router).
- **Стилизация:** Чистый CSS / CSS-модули / Tailwind CSS (использование Flexbox и Grid обязательно).
- **UI библиотеки**: для готовых компонент по желанию
- **Данные:** Локальный Mock-сервер

## Функциональные требования и роутинг

В приложении должно быть реализовано минимум **2 отдельные страницы** и один сквозной компонент Header

### 1. Шапка сайта (Компонент Header)

- Отображается на всех страницах приложения
- Содержит логотип (ссылка на главную страницу) и **индикатор корзины** с динамическим счетчиком билетов (например: `🛒 Корзина (2)`), который ведет на страницу корзины

### 2. Главная страница (`/`) — Поиск и результаты

- **Форма фильтрации:**
  - Поле ввода текста для фильтрации по городу прибытия («Куда»). Фильтрация должна происходить налету (клиентская) или по нажатию кнопки
  - Переключатель (табы или радиокнопки): _«Все рейсы»_ и _«Только прямые»_
- **Список рейсов:**
  - Отображает карточки рейсов, полученные с Mock-сервера
    - вид карточки - горизонтальная полоса из 3х колонок: авиакомпания и время вылета | маршрут откуда и куда | цена и кнопка
  - Если рейс уже добавлен в корзину, кнопка покупки на карточке должна заменяться на текст _«В корзине»_ и становиться неактивной (`disabled`)

### 3. Страница корзины (`/cart`) — Выбранные билеты

- Отображает список всех добавленных билетов
- У каждого билета должна быть кнопка **«Удалить»**
- Снизу выводится **«Итоговая стоимость»** всех билетов в корзине
- Кнопка **«Оформить заказ»**, которая при клике очищает корзину и выводит простое уведомление об успешном бронировании (через `alert` или кастомный нотификатор)

## Логика добавления билетов

1. При добавлении билета на главной странице счетчик в `Header` увеличивается, а кнопка покупки блокируется
2. При удалении билета на странице `/cart` сумма пересчитывается, счетчик уменьшается, а на главной странице кнопка этого рейса снова становится активной

## Требования к вёрстке

- **Flexbox:** Для выравнивания элементов внутри `Header` (логотип слева, корзина справа) и элементов внутри строки фильтров
- **Grid:** Для отображения списка рейсов (сетка карточек) либо для внутренней структуры самой карточки билета (например: лого/информация | линия полета | цена и кнопка)
- **Адаптивность** (опционально) Перестроение списка рейсов для малых экранов. Цель: добиться аккуратного вида на каждом расширении экрана

## Настройка Mock-сервера

Для имитации работы бэкенда используйте любое расширение для VSCode (например, **Mock Server** от Thinker, **JSON Server** или аналогичные).

Сервер должен отдавать список рейсов по адресу `http://localhost:XXXX/api/flights` (или любому другому локальному порту).

## Опциональные задачи

Выполнение любого из этих пунктов будет большим плюсом

1. Изменить схему расположения элементов в карточке рейса для малых экранов: элементы должны выстраиваться в столбец
2. Добавить анимацию счётчика при добавлении билета в корзину (например, "подпрыгивание")
3. Реализовать тёмную тему и переключатель в Header
4. Синхронизировать корзину с localStorage. При перезагрузке страницы или при полном закрытии вкладки выбранные билеты не должны пропадать
5. Изменить логику корзины. Вместо блокировки кнопки «В корзине» на главной, позволить кликать на неё бесконечно. В самой корзине одинаковые билеты должны группироваться в одну строку с кнопками [ + ] и [ - ] для изменения количества, а также автоматическим пересчетом итоговой стоимости
6. Добавить блок сортировки над списком рейсов: «Сначала дешевые», «Сначала дорогие» и «По популярности»
7. Страница с деталями маршрута `/flights/[id]` Сделать кликабельным название рейса или кнопку «Подробнее». При клике открывается отдельная страница конкретного рейса, данные для которой запрашиваются с мок-сервера по id (например, GET /api/flights/3).
8. Использовать встроенные возможности Next.js для обработки ожидания (файл loading.tsx или скелетоны карточек во время fetch-запроса) и ошибок сети (файл error.tsx).
